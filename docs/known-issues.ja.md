# 既知の問題とレビューのバックログ

このファイルは、正確性、APIの形状、機能の完全性、テスト、およびアプリケーション統合に影響を与えるレビュー結果を追跡します。動作が修正されテストでカバーされるまで、ここにエントリを保持してください。

## 正確性

| ID | ステータス | 領域 | 発見内容 |
| --- | --- | --- | --- |
| #1 | 修正済み | 行ハッシュ | クロスエンジンの行ハッシュが異なるダイジェストアルゴリズムを使用していました。PostgresはMD5を出力し、MySQL/SnowflakeはSHA2-256を出力し、OracleはSTANDARD_HASHを使用していたため、同一のPostgres -> MySQLの行がすべて変更されたように見えることがありました。行ハッシュは現在、エンジンごとにMD5互換のSQLを使用しています。 |
| #2 | 修正済み | 行ハッシュ | 行ハッシュの入力は区切り文字のみの連結を使用しており、単射ではありませんでした。プランSQLは現在、標準的な長さ接頭辞付きセルエンコーディングを使用しています。 |
| #3 | 修正済み | SQL識別子 | 識別子の引用が重複しており、`plan`には括弧や事前引用を含む名前のためのエスケープハッチがありました。プラン、チェックサム、および標準SQLは現在、1つの方言対応識別子レンダラーを共有しています。 |
| #4 | 修正済み | チェックサム | チェックサムSQLはエンジン認識になりました。サポートされていない関数/集約の組み合わせは `IRODORI_UNSUPPORTED_CHECKSUM_SQL(...)` で失敗し、MySQLのMD5整数変換はPostgresに合わせて符号付き64ビットの意味論を使用します。 |
| #5 | 修正済み | 標準化 | Postgresの浮動小数点丸めは `NUMERIC` を経由してキャストし、ブールの標準化はNULLを保持し、MySQLはもはやサイレントNULLの `CONVERT_TZ` を出力せず、安全でないUTCタイムスタンプモードはlakehouse/Trinoスタイルのエンジンで失敗します。 |
| #6 | 修正済み | スキーマ | 主キーの変更は差分化され、破壊的ラベル付きのPK削除/変更を伴うドロップ/追加主キー文としてレンダリングされます。 |
| #7 | 修正済み | スキーマ | 破壊的ラベルは型の狭窄、NULL許容の厳格化、リスクのあるNOT NULL列追加、PK削除/変更、制約削除をカバーし、インデックス削除はデータ破壊的とは見なされません。 |
| #8 | 修正済み | スキーマ | 非互換な `AlterColumnStyle`/方言の組み合わせは、他の方言にPostgres形状のSQLを出力する代わりに型付きのサポートされていないマイグレーションエントリを返します。 |
| #9 | 修正済み | SQLインポート | SQL文字列出力はMySQLスタイルの方言でバックスラッシュをエスケープし、区切り付きエクスポートはスプレッドシートの数式のように見えるテキストフィールドを保護します。 |
| #10 | 修正済み | エンコーダー | エンコーダーとインポート推論は非有限浮動小数点を `0`、`NULL`、または無効なSQLリテラルに静かに変換するのではなく拒否します。 |
| #11 | 修正済み | インポート推論 | CSV/JSONインポート推論は先頭ゼロの数値テキストを保持し、サイズ超過の符号なしJSON整数をテキストとして保持し、ヘッダーからUTF-8 BOMを除去し、安全なCSVからSQLリテラルへの処理を共有します。 |
| #12 | 修正済み | Avro | `AvroEncoder` は `Box::leak` でスキーマをリークし、`Record::new(...).unwrap()` を使用していました。現在はスキーマを所有し、短命なAvroライターを `finish` で通じて書き込み、無効なスキーマ/フィールド名に対して `io::Error` を返します。 |
| #13 | 修正済み | Parquet/プレビュー | Parquetエクスポートはすべての行を保持するのではなく境界付きの行グループをフラッシュし、インポートプレビューは表示行、スキャン行、JSONバイトの上限を別々に持つため、プレビューパスはデフォルトで無制限の入力を歩かなくなりました。 |

## 設計とAPI

| ID | ステータス | 領域 | 発見内容 |
| --- | --- | --- | --- |
| #14 | 修正済み | 方言API | `MigrationEngine` は共有の `SqlDialect` アクセサを公開し、プラン/チェックサム/標準テーブルレンダリングは共有パスを使用し、ホットパスのエンジンマッチは包括的でキャッチオールのデフォルトではありません。 |
| #15 | 修正済み | テーブル参照 | `TableRef` はカタログ/スキーマ/名前の部分をモデル化し、`SqlDialect::quote_qualified_identifier_if_needed` を通じてレンダリングし、空、空の部分、または過剰に修飾されたドット区切り入力に対しては失敗します。 |
| #16 | 修正済み | エラー | `try_build_migration_plan` は無効なテーブル参照、キー列の欠如、空の列名、空のハッシュ入力に対して型付きの `MigrationPlanError` を返し、空の行ハッシュ式は `IRODORI_UNSUPPORTED_SQL(...)` で失敗します。 |
| #17 | 修正済み | 公開API | `MigrationSpec`/`ForeignKeySpec` はビルダーコンストラクタを持ち、`AdaptiveChunking` は境界付きの次チャンクサイズとスロットル条件を計算し、同期修復出力は角括弧の疑似SQLではなく名前付きパラメータテンプレートとして型付けされています。 |
| #18 | 修正済み | スキーマモデル | スキーマ差分は現在、外部キー、CHECK制約、UNIQUE制約、主キー変更、テーブル/列/インデックス/制約のリネームヒントをモデル化します。 |
| #19 | 修正済み | エンコーダー | エンコーダーは行幅を検証し、非有限浮動小数点を一貫して拒否し、SQLブールの大文字小文字を正規化し、検証が必要な場合は失敗可能なコンストラクタ/書き込みパスを公開します。 |
